# Stories Module Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add authenticated collaborative stories with filtered discovery, 500-character openings, 140-character continuations, and transaction-safe alternating authors.

**Architecture:** Add a `stories` service package over the existing `*sql.DB`, with `stories` and `story_entries` tables. Keep HTTP/form handling in `actions` and page packages; enforce all limits and author-order rules in the service. Add three guarded Collage pages using Bootstrap utility classes only.

**Tech Stack:** Go 1.26, `database/sql`, CGO-free `modernc.org/sqlite`, Collage pages/actions/guards, SQLite transactions, existing Bootstrap CDN styling.

**Spec:** `docs/superpowers/specs/2026-09-27-stories-design.md`

## Global Constraints

- The existing SQLite connection must be reused; do not create a second database.
- The creator's opening entry is sequence 1 and counts as the creator's contribution.
- Opening text is at most 500 characters; continuation text is at most 140 characters.
- A user cannot add two consecutive entries to one story.
- Validation must live in the service as well as in forms.
- Form failures return status 422 and re-render the same page with field-specific errors.
- Do not create new CSS files; use Bootstrap utility classes and existing inline styles.
- SQLite must remain CGO-free.

## Review Focus

- Unicode character limits: add tests using multi-byte text and count runes, not bytes, in Task 2.
- Concurrent same-author submissions: add a transaction/locking regression test in Task 2.
- Missing and malformed story IDs: add action/page tests in Task 4.
- Empty filter and case-insensitive title/theme matching: add list tests in Task 2.
- Form errors must survive a page re-render and appear under the correct field: add action tests in Task 3.
